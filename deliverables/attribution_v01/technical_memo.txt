Two summary inputs contain period-normalized stock wealth paths, binary holding positions and actual period-start capital weights.

These definitions use only starting weights and the saved holding paths. The matched passive benchmark remains fully invested in those stocks; it is not volatility-matched, beta-neutral or dollar-exposure-matched. Annual benchmarks each begin at the selected year's public weights, then hold them without cross-stock rebalancing within that year. They are independent conditional comparisons. Their annual returns are not a compoundable continuous comparator.

Stock attribution uses a_i times the public sleeve return for public contribution, a_i times the passive sleeve return for matched-passive contribution, and a_i times their difference for holding-path contribution. Initial-allocation contribution is (a_i-b_i) times the passive sleeve return. The corresponding stock terms sum to portfolio returns and the two exact gap terms. These are accounting descriptions, not causal effects or estimates of alpha.

Monthly contribution and risk
A month's contribution to the selected-period return is the change in normalized portfolio wealth between adjacent month ends. Its public-minus-matched increment telescopes exactly to the selected-period holding-path difference. A stock's increment uses a_i times its wealth change over that month. Separately, contribution to that month's own return divides the increment by actual month-start portfolio wealth. Simple monthly percentage returns are compounded, not added.

Mean invested-dollar exposure averages sum_i[a_i*A_i(t-1)*q_i(t)] divided by public portfolio wealth before the interval. It uses previous wealth, never the same interval's realized return. It differs from the share of stock sleeves held. Maximum drawdown uses wealth/running maximum wealth minus one and includes the initial wealth of one. It is a daily-close, within-period statistic; intraday drawdowns are unobserved. The top-three concentration measure uses the three largest positive stock contributions divided by all positive contributions, and is blank if no contributions are positive.

Reproduction and validation
The source bundle contains code, two summary inputs, the protocol, result CSVs and editable Power BI sources. Input hashes identify the exact summaries. Run python -m unittest discover -s code -p 'test*.py' for ten fictional-data tests. Tests cover a hand-derived two-stock allocation decomposition, equal-weight identity, monthly additivity versus compounding, exposure based on previous wealth, initial-wealth drawdown, missing dates, invalid weights, nonzero-cost source rejection, inconsistent positions/returns and input preservation. Runtime checks also reconstruct each active sleeve's gross interval factor from the passive interval return and the saved holding position. Stock contributions, monthly increments, gap components and monthly compounding reconcile to portfolio totals. Downloaded input and original artifact hashes are rechecked. These are AI-assisted software/accounting checks, not independent human validation.

Design choices and rejected alternatives
Matching starting stock weights addresses a specific confound in the earlier annual comparison. It leaves exposure differences visible rather than calling them controlled. The original passive comparator is retained so readers can see the allocation effect. No ex-post leverage scaling is fitted to the observed return or volatility. There is no random-timing experiment, regression alpha, significance claim, optimal parameter search or causal AI-event attribution in this release. More elaborate tests would require a separately specified design.

The 2025 aggregate and stock results were known before this attribution protocol. Its results cannot be described as preregistered or out of sample. The initial protocol is retained; a later portability update changes file paths and hashes only, without changing financial or attribution rules. A current source hash is stronger provenance than an unsupported claim about a vendor release version.
